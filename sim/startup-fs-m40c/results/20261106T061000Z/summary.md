Append-only evidence. DUT: the settled P3 netlist (`sim/recentre/p3/rcosc_top_p3.spice`, DR-0023),
trim code 0xA9. Every probe is **one** corner (one process x one temperature), run with
`klt sim --backend local <request> -o out_<probe> --format json` (client `klt 0.9.2.dev47+g581de87616d8`,
ngspice-46, `gf180mcuC`); no grid was run locally. Requests are generated by `../../gen_probes.py`
into `../../probes/`; raw logs, decks and waveforms are in `out_<probe>/`, reports in `report_<probe>.json`.

## Root cause (classification: real design failure of the settled netlist, not a simulator artifact)

1. The state is a stable fixed point of the circuit model: it persists for 6 us from the DC step, and it is
   reached dynamically from a physical power-up ramp (vc starting at 0 V). It is not a failure to find a DC
   solution.
2. Mechanism: the high-side comparator (NMOS pair, `vc` vs `vh`) is overdriven (`vc` 2.0-3.3 V against
   `vh` 1.7-2.2 V). The pair device on the `vc` side goes deep into triode, so `dp` cannot fall below the tail
   node (dp - tail = 0.04 V). With the tail node at 0.8-1.1 V, `dp` bottoms at 0.8-1.2 V. At fs / -40 C the
   output inverter (NMOS fast and cold, PMOS slow and cold) has a switching threshold in that range, so
   `cmph_out` settles at 0.5-0.7 V instead of a logic high. That level cannot overcome the series-PMOS pull-up
   of the NOR latch (`qbar` stays 3.07-3.2 V), so the latch is never set, the discharge device stays off, and
   `vc` charges to VDD and stays there.
3. The failure needs fs / -40 C **and** a higher supply: fs at 27 C and tt at -40 C / 3.6 V both oscillate.
   At 3.0 V the same corner oscillates.
4. It is specific to the settled P3 netlist: the pre-re-centre schematic DUT oscillates at the same corner
   (`schem_fs_m40_v33`, 48.98 MHz), consistent with the pre-re-centre 63-point factorial reported in PR #225
   (fs / -40 C / 3.3 V started, 47.2 MHz). Which of the three P3 changes (extracted parasitics, ladder x0.70,
   PDK MiM card) moves the comparator into this state was **not** isolated here; that is part of the follow-up.

No workaround was applied: no `.ic`, no relaxed bench, no change to the ratified spec or to a corner list.
Rows 7 and 10 therefore stay FAIL at fs / -40 C / 3.3 V and 3.6 V (measured, not a bench error).
