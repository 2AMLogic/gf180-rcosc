# Comparator-H output-stage fix: settled-netlist evidence (issue #229, DR-0028)

The fix is `MBUFN W 2u -> 1u` in `design/rcosc_comparator.sch` (diagnosis: `../startup-bisect/`). This directory
holds the settled P3 netlist on the revised layout and the batch campaigns run on it.

| path | role |
|---|---|
| `gen_dut.py` | `klt extract --parasitics` of the revised `layout/cells/rcosc_top.gds` (needs klayout-tools 0.4.0 / klayout 0.30.12 on PATH) + the DR-0023 P3 transformation -> `rcosc_top_p3_cmphfix.spice`; extraction in `pex/` |
| `startup/`, `item5/` | `klt sim` requests generated by `sim/startup-settled/gen_requests.py --dut` and `sim/item5/gen_requests.py --dut` |
| `gen_calib.py`, `calib/` | single-corner (tt / 27 C / 3.3 V) calibration-code probes, run locally |
| `results/20261106T071000Z/` | batch-fleet envelopes: `report_v{30,33,36}.json` (startup), `item5/report_c*_v*.json` + `item5/rows.{md,json}` (15 envelopes), `out_*` receipts |

## Results

- Startup bench (ramp, 7 process x 3 T x 3 supplies = 63 points): **63/63 start**, worst settle 1.54 us
  (`../startup-settled/results/20261106T0735Z/`). Before the fix: 61/63, fs / -40 C at 3.3 V and 3.6 V NON-START.
- Item-5 campaign (15 envelopes x 21 corners): **every point returns a frequency**; rows 7 and 10 pass. Rows 2, 4, 5, 8
  still FAIL (pre-existing; row 8 worst 564.5 uA, was 576.2 uA) and row 1 now FAILS at code 0xA9 (+2.38 %), see below.
  The `ca9` requests at 3.3 V / 3.6 V exit 3 (`check_failed`) only because of the row-8 Iq limit at ff corners, as before.
- Controls: 3.0 V and fs / 27 C still oscillate. The frequency effect is large at the fs corner, where the old
  netlist was marginal rather than just stuck: fs / -40 C / 3.0 V 26.1 -> 47.4 MHz, fs / 27 C / 3.6 V 30.6 -> 50.5 MHz, and
  smaller elsewhere (sf +1.2 %, ff / -40 C / 3.6 V +21 %). tt / 27 C / 3.3 V moves 48.05 -> 49.14 MHz at 0xA9.
- Calibration code (`calib/`, tt / 27 C / 3.3 V): 0xA3 47.647, 0xA4 47.886, 0xA5 48.145, 0xA6 48.384, 0xA7 48.635 MHz.
  Re-centring the code is not done here (DR-0023 is still pending ratification).

Batch jobs: see each `report_*.json` `environment.remote.job_id` (aws-batch-fleet, spot, runner klt 0.9.0).

## Reproduce

```
export PATH=<venv with klayout-tools==0.4.0 klayout==0.30.12>/bin:$PATH
python3 -I gen_dut.py
python3 -I ../item5/gen_requests.py --out item5 --dut rcosc_top_p3_cmphfix.spice
python3 -I ../startup-settled/gen_requests.py --out startup --dut rcosc_top_p3_cmphfix.spice
KLT_SIM_BACKEND=batch klt sim item5/request_c<code>_v<VDD*10>.json -o OUT --format json > OUT_report.json   # x15, startup x3
python3 -I ../item5/report_rows.py results/<runid>/item5
```
