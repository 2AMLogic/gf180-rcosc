# T1 item 5 -- row-to-request map

Maps each ratified spec row (the ten rows of the top-level `README.md`
target-specification table, classified in
[DR-0019](../../spec/decision-records/0019-statistical-vs-deterministic-spec-rows-and-monte-carlo-evidence-plan.md))
to the `klt sim` request(s) whose envelope will decide it, or declares the
gap. Requests are generated by `gen_requests.py` into `requests/`
(`python3 sim/item5/gen_requests.py`; regenerating is byte-identical) and
checked by `test_item5_rows.py`.

**Status: requests only, nothing run.** The corner grid waits on #66 (settled
sizing) and a `gf180mcuC` batch runner; it is submitted with `klt sim` to the
batch fleet, never as a local grid. Item 5 stays `unmet` and no ratified row
or DR-0019 is edited here. Every request spans 7 process x 3 temperature
corners (21 points); the file name encodes trim code and supply
(`request_c<code, lowercase hex>_v<VDD*10>.json`). Each reports `fosc` and `iq_run_ua`.

`<c>` below stands for the codes named in the row, `v30|v33|v36` for the three
supplies.
